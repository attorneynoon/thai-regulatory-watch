These are not covered merely because the six requested categories work. No non-TCCT source object was changed.

The dedicated collector fetches all advertised pages before applying a category. It rejects pagination drift, duplicates, malformed or mismatched category data, draft/inactive records and truncated inventories. Source bounds are 50 pages and 1,000 records; the TCCT mode permits a finite maximum of 100 pages without changing the ten-page ceiling for other modes. Primary-PDF downloads use a TCCT-specific 40,000,000-byte bound; every listed attachment remains in source metadata even when it is not downloaded.

TCCT item identity is derived from its validated content UUID independently of the displayed URL. A PDF-only record can link to its actual file; a body/reference record can link to the actual category listing, labeled as a listing. Several records may legitimately share that link without collapsing into one item. The collector never fabricates an individual article route.

The migration marker is committed with the complete category transaction. Previously unseen UUIDs become BASELINE on that first migration; subsequent unseen UUIDs become NEW. Existing legacy observations and event identities are retained, without unverified filename aliasing. A PDF-only access failure degrades health but does not repeat the migration baseline. Replacing a primary PDF clears the old fingerprint, validators and check timestamps even when the replacement falls outside the current download budget.

## Evidence normalization

- Preserve id/code/title and raw start_date/end_date, including timezone.
- Keep category/sub_category/categories memberships as many-to-many data. Missing required evidence fields are schema failures; explicit null is different.
- Preserve non-null raw subcategory IDs when the optional top-level expansion is omitted or null, with `source_subcategory_unresolved` and a distinct `sub_category_relation_state` of `omitted`, `null` or `resolved`. The membership relation field remains required. A resolved category key and ID must still prove the requested scope, and primary raw IDs must agree with membership raw IDs. An unresolved child cannot prove a year-specific scope. Do not invent a child category, year or reason for the absent relation. Populated child ID/parent mismatches, inactive categories and draft/inactive records remain failures.
- Keep file_list[].fileUrl and every attachment entry. URLs are extensionless https://api.tcct.or.th/upload/{UUID}; all 334 observed PDF entries had isPublic:false. That flag alone neither denies nor establishes downloadable public access.
- Preserve body text, description and external references from url_link and body hyperlinks. Do not require a PDF to retain a record.
- Keep unsafe or non-HTTPS body hrefs as inert source evidence; never upgrade or dereference them automatically.
- Exclude CMS owner data, counters and maintenance timestamps from semantic change detection.
- Leave legal effect Not assessed and review status unreviewed.

153 ruling records had a source-date/category-year difference (80 of 137 verdict; 73 of 169 mergers). This does not establish which field is wrong. Do not infer a decision, event, consultation-deadline or effective date from start_date, category year, filename or observation time.

Eight older draft-law hearing records had only a title; retain content_missing warnings. is_active means visible in this API contract, not an open hearing or binding law.

```bash
python scripts/qualify_tcct_live.py
```

The live qualification command reads only the registry, starts with empty in-memory state for each distinct API category, sets the PDF budget to zero and prints JSON. It never reads or writes the production monitor state, generated feeds or schemas. A failed or inconsistent scope returns a nonzero exit status. The PR-only CI job runs this command with read-only repository permission and verifies protected files remain unchanged. It does not invoke the production monitor workflow or deploy anything.

The optional `--diagnose-taxonomy` flag records the failed request and a scalar-only public taxonomy projection, including field-presence markers, then may inspect remaining advertised pages within the same transport, page, item and byte limits. It stops on access errors or metadata drift and never changes a failed scope into a qualified scope. Successful receipts include listing warning counts and a whitelist of affected record IDs, raw category IDs and relation states, so unresolved taxonomy and the distinction between omitted and null remain visible without exporting record bodies or CMS owners.
